# SP_themes: Spicetify theme studio

This repo makes Spicetify themes and publishes them to the Spicetify Marketplace by pushing to the public GitHub repo `BakerBelays/SP_themes` (topic `spicetify-themes`). The setup is Windows and PowerShell. Spicetify is on PATH, and its config lives in `%APPDATA%\spicetify`.

## Workflow

1. `/new-theme <Name> <description of the look>` scaffolds, designs, validates and installs a theme.
2. The user screenshots Spotify and saves it as `themes/<Name>/preview.png`.
3. `/test-theme <Name> [Scheme]` turns on live reload while tweaking.
4. `/publish-theme [message]` validates, rebuilds the manifest, commits and pushes.

Run scripts as `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/<Script>.ps1 ...` from the repo root.

## Layout

- `themes/<Name>/` holds one theme: `color.ini` (schemes), `user.css`, `theme.json` (the metadata source for the manifest: name, description, tags, authors, optional include), `README.md` and `preview.png`.
- `template/` is copied by New-Theme. Placeholders: `{{NAME}}`, `{{DESCRIPTION}}`, `{{SCHEMES}}`, `{{USER}}`, `{{REPO}}`.
- `scripts/lib/Common.ps1` holds the shared helpers: JSON writer, color.ini parser, and `Invoke-Native`, which stops PS 5.1 from turning native stderr into errors. Keep every script ASCII-only.
- `manifest.json` is generated by Build-Manifest.ps1.

## Scripts

| Script | Purpose |
|---|---|
| `New-Theme.ps1 -Name X [-Description] [-Tags a,b]` | Copies template to `themes/X`, fills `theme.json` and `README.md`. Refuses if the folder exists. |
| `Test-Theme.ps1 -Name X \| -All [-SkipPreview]` | Checks that the files exist, every scheme has all 15 keys with 6-digit hex values, `theme.json` has a name and description, the CSS braces balance, and the preview is a real PNG. |
| `Install-Theme.ps1 -Name X [-Scheme S] [-Watch]` | Creates a junction `%APPDATA%\spicetify\Themes\X` → `themes/X`, then `spicetify config` + `apply`. `-Watch` runs `spicetify watch -s`. |
| `Build-Manifest.ps1` | Writes `manifest.json`: an array sorted by name, with `branch: main`, UTF-8 without BOM, 2-space indent. |
| `Publish-Themes.ps1 [-Message] [-Yes]` | Runs Test -All, then Build-Manifest, then commit, `--add-topic spicetify-themes`, and `git push origin main`. |

## Rules

- Never hand-edit `manifest.json`. Edit `theme.json` and run Build-Manifest.ps1.
- Run `Test-Theme.ps1` before any commit.
- Never publish a theme without `preview.png`.
- Never force-push and never rewrite history (no amend or rebase of pushed commits).
- Pass `Publish-Themes.ps1 -Yes` only after the user has typed yes to the exact action it printed.
- Spotify class names change between versions. Prefer `--spice-*` variables and stable attributes (`data-testid`, `aria-label`) over hashed class names. Spicetify-mapped classes (`.Root__*`, `.main-*`, `.x-*`) are acceptable.
- `color.ini` values are 6-digit hex with no `#` and no inline comments.
- `include` URLs in `theme.json` must not be raw.githubusercontent.com. Use GitHub Pages.

## Model selection

- Use Sonnet 5.5 (`claude-sonnet-5-5`, the project default) for normal work.
- Use Haiku 5.5 (`claude-haiku-5-5`) for single-value edits and re-publishing.
- Switch to Opus 5.5 (`/model opus`) only when Sonnet fails twice on the same Windows or PowerShell problem.
- Do not use Fable 5.1 for this project.
